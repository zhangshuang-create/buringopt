# 当前轨迹生成思路与最终排序说明

本文档对应当前 `optcut723.py` 中 `generate_seam_aware_trajectory(...)` 的实现，目的是把“轨迹怎么生成”以及“每段轨迹最后怎么排序串接”说明清楚，方便后续排查和继续优化。

## 1. 总体目标

这套逻辑的目标不是简单在 UV 上画平行线，而是：

- 先以主缝两侧的对应关系建立一个稳定的局部规划坐标系；
- 再把轨迹分成下半区、中间腰部、上半区三大块来生成；
- 对缝两侧的外侧区域，按照各自宽度独立布置扫描线，尽量让真实间距接近优化后的 `target_spacing`；
- 最后把所有扫描段按一条连续工艺路径串起来，自动补充跨段过渡线、跨缝跳转和 3D 平滑过渡。

最终输出不是“单纯一组扫描线”，而是一条已经排好顺序的工艺轨迹序列 `segments`。

## 2. 规划坐标系怎么建立

### 2.1 主缝对应关系

函数先通过 `_resolve_main_seam_uv_segments(...)`，把预切缝 `PrecutSeam` 中保存的几何顶点对，恢复成 UV 空间里缝两侧一一对应的线段集合 `seam_segments`。

可以理解为：

- `uv_a*` 是缝的一侧；
- `uv_b*` 是同一条物理缝在另一侧的 UV 副本；
- 之后所有“跨缝跳转”都依赖这组对应关系。

### 2.2 局部参考系

`_planning_frame(...)` 会从所有缝段中找出“缝两侧距离最窄”的位置，把它作为腰部参考宽度：

- 原点 `origin`：取腰部左侧点；
- `x_axis`：沿腰部横向，从左侧指向右侧；
- `y_axis`：沿轨迹主扫描方向，从下往上；
- `waist_width`：腰部宽度。

之后所有 UV 点都会先映射到这个局部坐标系：

- `x` 表示左右位置；
- `y` 表示上下位置。

这样后续“上半区 / 下半区 / 左侧 / 右侧”的划分就有了统一标准。

## 3. 轨迹是怎么生成出来的

## 3.1 先把区域分开

在局部坐标系里：

- `y <= 0` 的顶点视为下半区参考；
- `y >= 0` 的顶点视为上半区参考。

然后分别计算四个外侧区域的横向宽度：

- `lower_left`
- `lower_right`
- `upper_left`
- `upper_right`

中间区域的宽度直接用 `frame.waist_width`。

所以当前实际上是 5 个物理区域：

1. 下左外侧
2. 下右外侧
3. 中间腰部
4. 上左外侧
5. 上右外侧

## 3.2 间距优化

`optimize_spacing(...)` 并不是直接决定所有区域的最终轨迹数，而是先根据三个代表尺寸做一次全局优化：

- 中间腰部宽度 `waist_width`
- 上半区平均外扩宽度
- 下半区平均外扩宽度

它会在 `0.9 * nominal_spacing ~ 1.1 * nominal_spacing` 内搜索一个更合适的 `target_spacing`，让各区域实际间距整体更接近目标值。

这个 `target_spacing` 是后面所有区域布线的共同参考。

## 3.3 四个外侧区域独立算轨迹条数

这是当前版本里很重要的一个改动。

以前上下半区左右两侧共用同一个 `upper_count` 或 `lower_count`，当左右宽度不对称时，窄侧会被强行塞进和宽侧一样多的轨迹，导致间距异常密集。

现在改成：

- `lower_left_count = max(1, int(np.round(extents["lower_left"] / target_spacing)))`
- `lower_right_count = max(1, int(np.round(extents["lower_right"] / target_spacing)))`
- `upper_left_count = max(1, int(np.round(extents["upper_left"] / target_spacing)))`
- `upper_right_count = max(1, int(np.round(extents["upper_right"] / target_spacing)))`

然后分别调用 `_balanced_outer_positions(...)` 生成各自的 `x` 坐标。

这样每个外侧区域都按自己的物理宽度独立均分，最终实际间距会更接近同一个 `target_spacing`，不会再出现窄侧严重堆叠。

## 3.4 中间腰部轨迹

中间腰部仍然保持原有逻辑：

- 使用 `optimum.counts[0]` 作为中心区轨迹数；
- 通过 `_balanced_center_positions(...)` 在腰部范围内均匀放置；
- 要求中心轨迹数是正奇数，保证中轴附近的分布对称。

## 3.5 每条候选线如何判断可用

仅仅有 `x` 坐标还不够，还要判断这条竖线在当前区域里是否真的落在曲面 UV 域内部。

这里的流程是：

1. `_line_domain_intervals(...)` 求一条 `x = 常数` 直线与 UV 三角面的交段；
2. `_region_interval(...)` 再按 `upper / lower / full` 选出当前区域对应的有效区间；
3. `_available_tracks(...)` 或 `_available_center_tracks(...)` 过滤掉无效轨迹。

所以真正进入后续排序的，并不是“理论上该有的全部位置”，而是“几何上确实能扫到的有效轨迹”。

## 3.6 扫描线如何落到 3D

一旦某条轨迹的 `x` 和 `y` 扫描区间确定：

- `_sample_scan_uv(...)` 会在 UV 中按 `sample_step` 采样；
- `_UVToXYZMapper.map(...)` 把采样点映射回 3D；
- 生成一个 `TrajectorySegment(kind="SURFACE_SCAN")`。

所以实际喷涂走的是 3D 点列，不是直接使用 UV 折线。

## 4. 最终每段轨迹是怎么排序的

当前排序不是单纯按 `x` 从左到右，而是按“尽量连续、尽量少跨大距离、跨缝后继续相邻区域”的原则来组织。

整体顺序固定为：

1. 下半区
2. 中间腰部
3. 上半区
4. 最后再对跨缝跳转做 3D 平滑

下面分别说明。

## 4.1 下半区排序：按左右配对的 Master-Slave 方式

下半区先取：

- `lower_left`
- `lower_right`

然后用：

- `paired_lower = max(len(lower_left), len(lower_right))`

按索引一对一向外遍历。这里保留了原来的“多边配对 + 单边自动补线”思想：

- 如果左右都有第 `i` 条，就组成一对；
- 如果某一侧没有了，另一侧还能单独继续生成。

### 下半区一对轨迹内部的顺序

每一对里分两段：

1. 第一段 `Master`：从当前选择的一侧向上扫；
2. 第二段 `Slave`：通过主缝映射到另一侧后，再向下扫。

具体过程：

1. 用 `choose_nearest_side(...)` 比较左侧和右侧候选轨迹的起点，到上一条已完成表面轨迹终点 `last_surface.xyz[-1]` 的 3D 距离；
2. 谁更近，谁就先作为本对的第一条 `Master`；
3. 第一条结束后，用 `_seam_projection_and_counterpart(...)` 找到它在主缝上的对应点；
4. 插入一个 `SEAM_JUMP`；
5. 再由 `_make_scan_from_seam_destination(...)` 在缝对侧生成第二条 `Slave`。

所以“下半区左右哪边先扫”不是写死的，而是动态选择更靠近上一条终点的那一侧。

这也是为了减少错误的长距离过渡线。

## 4.2 中间腰部排序：双向候选，择近启动，之后蛇形往返

中间区先拿到全部 `center_inner`。

然后构造两种候选顺序：

- `ascending_tracks`：按当前中心轨迹自然顺序；
- `descending_tracks`：反过来。

如果前面已经完成了下半区，则会比较：

- 采用正向时，第一条中心轨迹起点与 `last_surface` 终点的距离；
- 采用反向时，这个距离是多少。

谁更近，就用谁作为中间区的起始方向。

确定起始顺序后，中间区扫描采用蛇形方式：

- 第 0 条向上；
- 第 1 条向下；
- 第 2 条向上；
- 第 3 条向下；

也就是 `upward=(index % 2 == 0)`。

这样可以最大限度保持相邻中心轨迹之间的连续性，只需要补很短的区域内过渡线。

## 4.3 上半区排序：同样按左右配对，但优先接中间区相邻的一边

上半区逻辑与下半区对称：

- 使用 `upper_left`、`upper_right`
- `paired_upper = max(len(upper_left), len(upper_right))`
- 每一对仍然是 `Master + 跨缝 + Slave`

区别在于：

- 上半区第一条 `Master` 是向下扫；
- 对侧 `Slave` 再向上扫。

### 上半区起始侧的关键点

这里当前也使用了 `choose_nearest_side(...)`。

也就是说，在进入上半区的第一对轨迹时，不再固定从左边开始，而是：

- 比较 `upper_left[0]` 和 `upper_right[0]` 两条候选线的起点，
- 看谁离“中间区最后一条轨迹的终点”更近，
- 谁更近就先扫谁。

这正是为了解决你前面提到的那个问题：上半部分第一条不应该直接去连最后一条，而应该优先连接和当前终点相邻的中心区域轨迹。

## 4.4 过渡线怎么插入

所有表面扫描段都不是直接裸拼，而是通过 `append_surface(...)` 统一追加。

它内部维护 `last_surface`，并根据情况决定是否先插入一段 `OVERTRAVEL`：

- 如果当前段和上一段需要连续连接，就调用 `_overtravel_segment(...)`；
- 这段过渡线是 3D 空间中的非喷涂连接段；
- 它根据上一段出口方向和下一段入口方向，构造一个“抬出去再回来”的四点连接。

因此最终轨迹序列里会穿插：

- `SURFACE_SCAN`
- `OVERTRAVEL`
- `SEAM_JUMP`

而不是所有扫描线简单首尾直连。

## 4.5 跨缝跳转的最终处理

在下半区和上半区，每当一对轨迹需要从缝一侧切换到另一侧时，代码先插入一个 `SEAM_JUMP` 标记段。

但函数末尾并不会直接把这段 UV 跳线当成最终 3D 运动，而是调用：

- `_smooth_seam_jumps_xyz(...)`

它会扫描如下模式：

- `SURFACE_SCAN`
- `SEAM_JUMP`
- `SURFACE_SCAN`

如果发现这个三段组合，就把它重写为更平滑的 3D 过渡：

1. 先把前一条扫描尾部裁短一点；
2. 再把后一条扫描头部裁短一点；
3. 用 `_cubic_xyz_blend(...)` 在两者之间生成一段三次曲线；
4. 保留一个空的 `SEAM_JUMP` 作为语义标记；
5. 真正的 3D 运动由 `SEAM_BLEND_3D` 完成。

所以最终机床真正执行时，跨缝不是一条硬折线，而是一段 G1 更连续的平滑过渡。

## 5. 可以把最终排序理解成下面这条主流程

```text
下半区第1对
  -> 必要时补 OVERTRAVEL
  -> Master 扫描
  -> SEAM_JUMP
  -> 对侧 Slave 扫描
  -> 下半区第2对
  -> ...
  -> 中间区起始方向择近
  -> 中间区蛇形往返扫描
  -> 上半区第1对起始侧择近
  -> Master 扫描
  -> SEAM_JUMP
  -> 对侧 Slave 扫描
  -> 上半区第2对
  -> ...
  -> 将所有跨缝跳转替换为 SEAM_BLEND_3D 平滑段
```

## 6. 当前版本的几个关键特征

### 6.1 排序策略的核心

当前排序并不是“严格按几何左到右”，而是同时考虑：

- 区域顺序：下 -> 中 -> 上；
- 左右配对关系；
- 与上一条轨迹终点的 3D 邻近性；
- 跨缝后的对侧连续接续；
- 区段之间的非喷涂过渡成本。

### 6.2 最近两项关键修正

当前版本已经包含两个非常重要的修正：

1. 四个外侧区域独立计算轨迹数量，避免宽度不对称时窄侧轨迹过密。
2. 上下外区每一对轨迹的起始侧由 `choose_nearest_side(...)` 动态决定，避免第一条上半区轨迹错误连到远端，改为优先连接和当前终点相邻的中心区域。

## 7. 最终输出里每种段的含义

- `SURFACE_SCAN`：真正贴着工件表面喷涂的扫描段。
- `OVERTRAVEL`：两条表面扫描之间的非喷涂 3D 过渡段。
- `SEAM_JUMP`：跨缝语义标记，表示这里发生了从缝一侧到另一侧的对应切换。
- `SEAM_BLEND_3D`：对 `SEAM_JUMP` 做 3D 平滑后的实际运动段。

从工程角度看，最终导出的 CSV 已经不是“候选轨迹集合”，而是按工艺执行顺序排好的完整路径。

## 8. 一句话总结

当前 `generate_seam_aware_trajectory(...)` 的思路可以概括为：

先用主缝建立局部坐标系，再按下/中/上和左右区域独立生成有效扫描线，随后依据“与上一段终点的邻近性 + 左右配对 + 跨缝映射”把各段串成一条连续轨迹，最后把跨缝处替换成更平滑的 3D 过渡。
